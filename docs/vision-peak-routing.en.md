# Time-based vision routing in UTC+8: October 31, 2026

[中文](vision-peak-routing.md)

`vision_peak_routing_enabled` defaults to off and is enabled on the reference installation. It affects image reading only, without changing the global chat model, persona, memory scope, or speech service.

Following the [DeepSeek pricing schedule](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/), requests on weekdays in UTC+8 use `qwen3.8-omni-flash` from 09:00 inclusive to 12:00 exclusive and from 14:00 inclusive to 18:00 exclusive. Other times retain the original vision model. Weekends remain weekends even when designated as compensatory working days. The 2026 holiday intervals follow the [published State Council holiday notice](https://www.beijing.gov.cn/cs/gncs/zcwj/202603/t20260327_4568275.html). Additional holidays in later years can be specified in `vision-routing-calendar.private.json` in the plugin's private data directory, using `{"holidays":["2027-01-01"]}`. Unknown dates are not guessed to be holidays; maintain the calendar across years.

Routing is evaluated for each request, without an extra timer or restart. Screenmate and Bilibili image calls use the existing `bounded_generate` entry point. Pure-text background jobs do not switch. For ordinary QQ photos during peak hours, only the current images and question are sent to Qwen. Its temporary observations are returned to the original chat model, and the images are removed from the current request to avoid duplicate image reading. Private history, persona, and long-term memories are not sent with this independent vision request. This path still includes one text-response call to the original chat model; it does not make the entire turn free.

The key and regional endpoint reference the locally enabled `vision_qwen_key_provider_id` configuration, whose default is `aliyun_memory_embedding`; credentials are not copied into public configuration. Only official Alibaba Cloud regional HTTPS endpoints are accepted. Redirects, thinking, search, and automatic POST replay are disabled. If Qwen fails, ordinary photos retain their original input, while background image reads fall back to the original provider. Logs record only provider, usage, and fallback indicators, without credentials, image URLs, or contents. Free-quota deductions depend on actual Model Studio billing; switching does not guarantee every image will cost less.

All 675 regression tests at the time of this change passed. Coverage included the 09:00/12:00/14:00/18:00 boundaries, weekends, compensatory working weekends, holidays, the private calendar, temporary observations following successful photo reading, preserving the original photo on failure, and leaving pure-text requests untouched. A real tablet probe confirmed that the current Saturday retained DeepSeek and a simulated Monday at 10:00 selected Qwen. Each provider correctly answered a real request with a synthetic image containing no private material. Temporary TextPart compatibility and QQ online status were checked. The probe was removed; no QQ test message or Bilibili comment was sent, and NapCat was not restarted. The continuous desktop-watching state was unchanged.

The code and documentation are included in this GitHub update. Screenmate itself does not need a change or restart because its bridge accesses the current capability plugin for each request.

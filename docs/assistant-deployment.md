# 用DSH或类似助手辅助部署

[English](assistant-deployment.en.md)

这里的DSH或其他编程助手负责协助检查和配置，不替代AstrBot运行插件。不能把本仓库直接复制进另一框架就声称兼容。可以复制以下提示词，并自行填写设备信息；不要填写密码、Key或Cookie。

```text
请辅助我从零部署 https://github.com/FigaroGao/astrbot-fish-capabilities 。
设备：[系统、CPU架构、内存、是否已有Termux/Ubuntu/Python]。
先读取仓库 README、docs/getting-started.md、docs/release-0.7.0.md、
docs/privacy.md 和验证说明，再检查我的实际环境与版本。
先备份已有配置，避免覆盖正在运行的QQ或启动第二份NapCat。
第一阶段只做NapCat+AstrBot的QQ文字聊天；第二阶段只装主插件并测试香港天气；
后续逐项配置授权范围，再处理时间表、B站、云端记忆及可选语音识别。
明确标注每条命令在原生Termux、Ubuntu还是电脑终端执行，使用实际路径。
不要复制作者身份、私人配置或记忆；不要把仓库根目录当单个插件安装。
缺凭据时让我在本机可信界面输入，不要求发进对话或提交Git。
GCP补丁不匹配、LivingMemory接口缺失或原生依赖失败时报告实际缺口，不假装完成。
公开评论、动态及账号写入在我明确开启前保持关闭。
最终列出实际执行、验证成功、尚未测试、回退方法与日常启动命令。
```

## 交付检查

请助手给出实际安装目录、Python路径、版本、服务管理方式和已启用开关；不要给出真实凭据。逐项确认QQ收到回复、天气调用有结果、群范围隔离、任务可列出暂停、截图/日志经过脱敏。配置备份和登录数据不上传仓库。

如果只想迁移部分能力，明确说“只装天气和时间表，其他关闭”。模型能讨论某能力不表示它已有接口。让助手依据源码和回执判断，不依据另一个机器人的回忆补造配置。

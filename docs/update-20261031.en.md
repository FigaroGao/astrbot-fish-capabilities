# October 30–31, 2026: changes, migration and validation

[中文](update-20261031.md) | [English — full translation](update-20261031.en.md)

This update builds on the October 29 remote version and adds the subsequent reusable implementation. Shared capability switches remain disabled by default. No maintainer accounts, timetable, main persona prompt, conversations, memories, voice bindings or credentials are included. The desktop companion lives in its own repository: [Xiaojing-Screenmate](https://github.com/FigaroGao/Xiaojing-Screenmate).

## Feature changes

| Feature | Changes and limits |
| --- | --- |
| Ordinary Bilibili videos | Visual strategy 10: after preview classification, obtain a source available under normal playback permissions and allocate overview frames using low-resolution scene changes. The model then selects actual IDs, crops or time windows, and frames are extracted again from that same source. Up to two 30-second windows and six detail images; this is not complete frame-by-frame viewing or audio understanding. |
| Chat/slideshow videos | Keep the original page-reading route. When the discovered-page budget is exceeded, sample across the decoded timeline and report the budget limitation instead of treating the opening seconds as the entire video. Brief flashes and blurred text may still be missed. |
| Bilibili mentions and dynamic replies | Owner mention notices reply to the actual original comment using its wording and video evidence. A missing original comment ID stops posting rather than creating an unrelated root comment. Dynamic-thread targeting, reply state and comment-target validation are repaired; existing permissions and review remain. |
| Context cost | Remove accumulated reasoning fields from completed historical turns while preserving content required by the current tool-turn protocol. Replace old image/audio/video content from completed turns with markers; preserve text and current media still being processed. Request compaction does not delete original databases or files and does not promise a fixed cost reduction. |
| Everyday companionship | Add a supplementary everyday-interaction style encouraging grounded preferences and natural conversation without constant advice, summaries or introductions. Retain honest capability limits, avoid invented bodily experiences, and do not turn fictional video characters' experiences into the bot's own memories. No private main persona prompt is distributed. |
| Acknowledge slow work | In authorized owner-private interactions, briefly acknowledge slower browsing, video, weather, Canvas and shop tasks before execution. Deduplicate acknowledgements within the same turn; background schedules do not send extra task receipts. An acknowledgement is not a success claim. |
| Confirmed Lecture timetable | `fish_course_progress(operation="schedule", query="周一")` queries a locally confirmed recurring Lecture plan; aliases reuse course bindings. Without a private timetable, do not guess times, infer that the owner is currently in class, or automatically create reminders. |
| Read-only VALORANT stability | Retry confirmed read-only timeouts a limited number of times. If synchronization fails and cached data exists, explicitly return stale data and refresh failure; invalid login sessions still require the user's verification. Improve read-error handling without promising that every account field is always available. |
| Vocu TTS | Add an optional adapter and a local hidden-key entry tool. Convert synthesis output to 16 kHz mono PCM for the existing QQ voice pipeline. Do not automatically retry uncertain paid requests or publish users' voice IDs or keys. |

## Video upgrade

Continue using `bili_visual_enabled`, `bili_storyboard_enabled` and `bili_gallery_scan_enabled`; no new account permission is enabled by default. The runtime needs ffmpeg. Source downloads are limited to 96 MiB and ten minutes, and temporary source files are cleaned after completion or cancellation. Strategy 10 invalidates older visual-reading cache entries and then reuses the existing cache.

Scene scanning uses only two frames per second at 64×36; the overview retains timeline endpoints and time ranges. Detail images have a maximum dimension of 1600 without upscaling low-resolution sources. Ad handling still requires observed endpoints, explicit commercial evidence and high confidence; a brand alone is insufficient. Unavailable sources report `scene_fallback` and revert to previews. The ordinary route uses at most three vision calls: existing classification/character references, new overview selection, and final interpretation. It installs neither DSH, an additional resident model nor local ASR, and does not promise the reference project's 384-token accounting.

Results include `scene_overview_zoom`, scene intervals, selected windows and the actual frame manifest. Downloading a source does not mean the whole video was watched or heard. See the [scene overview and detail guide](bili-scene-v10.en.md).

## Local configuration and migration

Back up your own source, configuration and data before upgrading. Replace program files and reload the capability plugin; do not overwrite live settings with the disabled example. A NapCat restart is generally unnecessary. This update does not change comment budgets, scheduled tasks or owner authorization scopes.

Place the timetable in `owner-lecture-schedule.private.json` in the plugin's private data directory and have the owner verify its contents. See the [private timetable example](../examples/lecture-schedule.example.json). It is available only in owner-private queries and must not be uploaded to GitHub. Existing Canvas bindings and course-progress functionality remain unchanged.

For Vocu, install ffmpeg and copy the [preset structure](../examples/vocu-setup.example.json) to `vocu-setup.private.json` in the same private directory. Enter a voice ID you are authorized to use and your chosen speech rate. Run `python tools/vocu_login.py` to enter your own key without echoing it; the tool saves local credentials and selects Vocu. Then manually reload the plugin. Computer deployments may set `ASTRBOT_ROOT` to the installation directory. `tts_provider` still defaults to `sambert`, and `tts_enabled` defaults to false. Setup does not perform paid synthesis; actual Vocu generation and QQ delivery still require a user-verified short-utterance test.

## Validation

The development source passed 659 regression tests, and the final share directory passed 660; both runs had one existing audioop deprecation warning. New video tests cover ordinary/chat routing, time-window selection, invalid IDs/windows, ad exclusion, source dimensions, real ffmpeg synthetic video and cleanup. Existing mention fixtures were updated with the current interface's paused state and original comment ID; production validation was not relaxed.

The reference tablet's actual Ubuntu environment passed the complete synthetic-video pipeline: six overview frames, four detail frames, a 480×160 lower-half crop from a 480×320 source, and successful temporary-directory cleanup. A runtime probe confirmed strategy 10, scanner/ffmpeg availability and healthy QQ/OneBot state. The temporary probe was removed, and NapCat was not restarted. This test used fixed model output without real Bilibili-source downloads, actual vision-model calls or public posting; it therefore does not establish real-site success rates or model selection accuracy. Other users must validate their own accounts, source quality, network and device performance.

# Brain Core：共享决策与分轮修补

[中文](brain-core.md) | [English — full translation](brain-core.en.md)

本次将现有QQ、Autonomy、B站和Screenmate决策接到共享工作状态与注意力协调，复用既有执行器。主脑不接管全部工具实现，也不强制每个事件多调用一次模型。普通私聊与明确工具请求仍沿用AstrBot原生流程。

## 实际接入

| 路径 | 共享部分 | 保留的专业能力 |
|---|---|---|
| QQ群聊接话 | 按群决策占用、主人交互优先、发送前复核 | 原意图判断、复杂任务过滤、群静音、完整分段发送 |
| 自主活动与主动私聊 | owner注意力通道、当前工作、抢占、发送占用 | 原Autonomy完成后冷却、少量关联动作、私聊候选与预算 |
| B站选片与互动 | 工作进度、候选话题、公开写入协调 | 多阶段视频理解、身份核验、原公开审核和共同预算 |
| Screenmate | 与主脑共用主动判断及联系冷却 | 截图、桌宠动作、语音和播放回执仍在[独立仓库](https://github.com/FigaroGao/Xiaojing-Screenmate) |

`services/brain.py`负责短期注意力与占用；`brain_context.py`读取现有AstrBot人格并附加任务上下文。LivingMemory继续承担长期记忆。独立审核、提取、视觉分析不注入完整人格或私人聊天。工作状态保存“观察到消息”的时间，不把过去一次互动称为持续聊天。

## 已修补的行为

- 主人输入可使旧主动决定失效；过期、被替换的模型结果不继续行动。旧自主轮次不能清除新实例的占用或覆盖其工作状态。
- 明确群请求不会仅因其他人连续闲聊而失效；原提问者后续改变、新明确请求及静音仍会影响旧草稿。上下文不足时不猜测同意。
- 尚未发送就被抢占，与部分发送、网络结果未知分开处理。前者可以释放预约；后者不自动补发。公开传输被取消也保留不确定状态与防重复限制。
- 主动私聊重复唤起不清空在途活动摘要。生成草稿与协议端接受的文字分开；后者也不等于对方已读。
- 已读视频可进入有来源的话题候选，不要求立即推荐。普通私聊可用现有`fish_bili_memory`的可选`use_topic_id`声明本轮使用候选；只有完整正常模型文字被协议端接受，才记录讨论。工具回应、部分发送、错误结果和过期计划不算完成。未声明或绕过普通send的路径不会猜测消费成功。
- 当前未完成工具链保留完整资料与必要协议字段，回答后再精简。旧视频资料保留来源时间、阅读编号及摘要/看法的原始依据；旧看法不会覆盖较新的来源。
- 滚动摘要分片为独立JSON，超长消息重复标出原角色及工具引用；不默认所有user角色都是主人。跨重载共享摘要锁，避免同段历史重复生成。
- 长工具结果压缩保留失败及提交/确认标记，通用JSON使用明确的截断预览；空查询不证明事实不存在。
- 已审核表达参考不再被新待审记录挤出召回；版本修改有事务保护，过期或归档记录不自动复活。重复开场提醒在生成前生效，不硬禁称呼、不事后机械改写，也不增加一轮润色模型。
- 角色具体名称优先于同一提及里的家族别名；多图观察区分图内说话人、引文与用户说明，不凭头像或气泡位置绑定当前身份。新增公共编辑释义见`knowledge/conversation`和`knowledge/culture`，每条保留出处与日期。

## 安装与升级

先阅读[从零部署](getting-started.md)，安装本仓库的能力插件及所需依赖，再配置自己的主人身份、平台、授权群及服务。分享版开关默认关闭，不携带个人角色卡、记忆、信件、登录态或API Key。

升级前备份插件源码、配置和插件数据目录；先在测试会话核对AstrBot版本、人格解析和工具注册，再逐项开启所需能力。SQLite状态按需追加表或键，源码回滚不要直接覆盖升级后新增的聊天与回执。Screenmate桥接需要与其独立仓库的共享主脑接口配套更新；仅更新本仓库不会自动更新电脑端。

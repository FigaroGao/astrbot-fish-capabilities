# 2026-10-29: courses, Canvas and on-demand queries

These are incremental fixes after 0.8.0; the October 28 update remains applicable. Shared switches default to off and accounts are empty. Personal course lists, alias mappings, study notes, login sessions, tokens and private letters are not distributed.

## Additions and changes

1. Forwarded-record images retain their original speaker node, nesting level and F1/F2 identifiers, with at most six images recognized per turn. Downloads allow specified public QQ CDN hosts only, enforce byte/pixel limits and refuse redirects. Temporary images are deleted afterward. Failures are explicit; unseen content is not guessed and forwarded instructions are not executed. Existing six-level, 80-node and 12,000-character limits remain.
2. Bilibili outgoing records: fish_bili_sent privately retrieves saved comments, threaded replies and future dynamic replies from the last 30 days, eight by default and at most twenty. It reuses the private activity log without injecting all records every turn. Missing historical text is not invented; submission receipts do not establish public visibility. Comment pauses were not cleared and old comments were not replayed.
3. Owner-shared videos default to a specific reaction or discussion of a joke after reading, without announcing the title, retelling the plot or producing a viewing report. Explicit requests for introductions, summaries or analysis still receive them. This differs from recommending autonomously discovered videos; discussing a video on QQ does not automatically authorize a public Bilibili comment.
4. Course notebook: fish_course_progress records course names and progress from the owner's explicit current wording and retrieves them on demand. Corrections use previous, preserve old records and exclude superseded versions by default. Videos, uploaded teaching material and model guesses do not establish personal study progress. No tasks are created automatically.
5. Brief VALORANT review: fish_valorant_review reads the latest synchronized match and compares it with at most five earlier matches of the same mode, excluding itself and separating competitive/unrated play from deathmatch. ACS uses score_avg, not performance score. Headshot figures describe hit percentages and changes use percentage points; valid sample counts are explicit. Historical headshot details reuse cached data only, without treating missing data as zero or batch-fetching details. Highest/lowest current-match ACS includes ties and is not a judgment of blame or personality. Check the match time rather than presenting old cached matches as live results. Login success text now distinguishes the recent list default of three/maximum five from statistics defaulting to twenty/up to thirty matches.
6. CityU Canvas: fish_canvas exposes fixed-host GET queries only for courses, assignments with the owner's submission state, and announcements. Pages contain twenty items, page numbers range from one to twenty, and has_more identifies pagination. Announcements use the API's default recent fourteen-day range. There are no submission, messaging or grade-modification operations. Tokens stay in local configuration, travel in the Authorization header and are never supplied to model arguments, chat or diagnostics; redirects are refused.
7. Course links: fish_course_context supports view/bind/links/unlink. The owner explicitly confirms an alias against an exact Canvas name, code or ID; the tool verifies it against the current account's course list. Conflicts are not silently rebound and ambiguous names require confirmation. Combined queries return the current page of assignments/announcements and the latest five valid personal-progress notes. Existing notes are matched by alias/code/official name without rewriting; unlinking does not delete notes. School information and owner statements remain distinct: assigned work or uploaded files do not prove the owner learned or submitted anything.

## Installation and use

Back up source and private data before upgrading. Copy the main plugin into AstrBot's actual plugin directory and install dependencies in its Python environment. Reload the capability plugin; NapCat does not need restarting. Preserve private configuration rather than overwriting it with the shared template.

For initial Canvas binding, set ASTRBOT_ROOT to the actual AstrBot root and run tools/canvas_login.py from this repository. The reference tablet's fish-canvas-login is merely a local shortcut to that script; this repository does not automatically install system commands. The script hides input with getpass, verifies users/self through a fixed GET request, saves private canvas.credentials.json with mode 600, and sets local canvas_enabled=true. Reload the plugin afterward. Never place a token in command arguments, chat, URLs or GitHub. Run the same script to replace an expired token; automatic renewal is not supported. Other schools' domains require separate review and adaptation.

Example requests: “Show my Canvas courses”; “Use [alias] for [exact course name or code]”; then “What assignments does this course have, and where did I leave off?” Record progress with “[course] covered [my exact progress] today; note that down.” Ask “Review the match I just finished” for a brief match review, or “What have you replied to recently?” for outgoing Bilibili records. These tools are restricted to the authorized owner's private chat; combined course queries require both canvas and history to be enabled.

## Validation and limits

The complete implementation passed 639 regression tests; the final publication package passed 640 tests, including the public default-configuration check. Native isolated-note tests covered recording, lookup, correction permissions, course links and group denial. Real Canvas queries returned nine courses and checked assignments/announcements for one course. Real Canvas combined with a temporary notebook passed link and combined-query checks without writing synthetic notes to production. Real account mappings remain local, not universal defaults.

Forward images passed synthetic download/cleanup and nested-attribution tests and loaded on the device. No recent forwarded card was available for end-to-end testing, so real forwarded-image cloud recognition still awaits the owner resending a sample. Shared-video style has one synthetic real-model sample, not a guarantee for every generation. Brief match review registration and group denial passed; the real match request then failed login/role verification. The owner subsequently rescanned, but a real match comparison has not been rerun in this publication, so end-to-end real review is not claimed.

Deployment preserved configuration and the core persona, except that Canvas installation added a disabled default and the owner's local binding later enabled it. NapCat was not restarted; QQ/OneBot remained online and temporary probes were removed. No test QQ messages, public comments or dynamics were sent, and Canvas was not modified. Private data and credentials are absent from this repository.

# 2026-10-28 fixes and migration

1. Bilibili video strategy v9: bound accounts use the normal authenticated SDK for metadata; unbound accounts use public requests. HTTP 412/429 triggers a persistent five-minute cooldown per BV, unaffected by changing frame counts. Optional subtitle failures no longer block available visual material. Identities are not rotated to bypass controls.
2. Autonomous browsing no longer has a fixed three-video cap: the model selects each batch and whether to continue. Each session retains a 600-second execution window, a ten-minute per-video ceiling, deduplication and stop-on-failure. At most one interesting item is shared. Unlimited item counts do not mean unlimited execution.
3. Autonomous dynamics get distributed opportunities between 10:00 and 23:00 Hong Kong time, using context from the last six hours. They do not race midnight quota resets or default to nighttime themes; the one-post-per-day limit remains. The new bili_dynamic_daytime_enabled switch defaults to false.
4. Own dynamics can respond to new comments from the bound owner through the existing ten-minute reply check. Initial activation does not replay old comments. Author, resource type, target and comment content are checked, followed by independent review; uncertain writes are not repeated. bili_dynamic_reply_enabled defaults to false. Comments still share a rolling 24-hour ceiling of 20.
5. Companionship addenda: casual minor mishaps should not produce abstract pain metaphors or unsupported severe-injury checklists. Quiet hours constrain proactive interruptions; a previous goodnight does not mean the owner must sleep now. Continue the current conversation when the owner continues. The core persona, history, memories and existing timetable are preserved.
6. Character recognition fixes: tool compression, autonomous reflection and nested video memories retain names, actual-frame evidence and limitations. Decoded-page fallback also performs matching. With references enabled, the initial pass normally covers up to 18 candidates, or up to 27 when explicitly requested; the planner chooses the final detailed selection. Alternate outfits or chibi forms are not automatically treated as different characters, and objects must not be invented from reference images.
7. Six priority references are supported: DeepSeek, GPT, Claude, and the three Sunbringers Dracaene, Lindverne and Eldreda. Public metadata includes names, appearance, sources and community meme explanations. The three-bowls pun requires relevant context; the mother-and-children meme is not an official family relationship. Images remain local and are not distributed with the repository. Runtime setup requires local reference files with matching hashes.
8. Bilibili comment drafts avoid habitual terminal periods. Where appropriate, choose one catalog emote as an ending or one approved public-pack image; neither is mandatory. Necessary punctuation and independent image/text review remain. QQ text and JSON are not rewritten, and reviewed text is not silently changed afterward.

## Configuration and validation

Shared switches still default to off and identities remain empty. Additional settings include bili_scroll_unlimited_enabled (false by default) and bili_scroll_session_seconds (600 by default). Back up before upgrading and install dependencies in the same Python environment. Reload the capability plugin; NapCat does not need restarting. Do not overwrite private configuration with the shared template.

The character fixes passed 617 full regression tests; the subsequent comment-style change reran 45 relevant tests. The publication package separately passed all 618 regression tests. A real Claude video was reread and its recognized name retained. Each of the three supplied Sunbringer reference clips matched its expected character; this is not an unseen-sample benchmark. Low-resolution meme clips still show omissions and variation, so arbitrary fan art is not guaranteed. The first two reference clips used page reading; some pages were incomplete, and candidate counts are not claimed as coverage.

Three synthetic sleep-boundary scenarios and two comment drafts were tested through real cloud models. Continued conversation received normal replies, while explicit goodnight received goodnight. Both comment drafts ended with valid emotes and no terminal period. No test QQ messages, public comments or dynamics were posted, and no images uploaded. Dynamic replies received real read-only checks, not public test replies; next-day natural scheduling was not tested across a date boundary. Prompt preferences do not guarantee every future response.

Configuration and the core persona were unchanged; NapCat was not restarted. Deployment hashes matched, temporary probes were removed, and QQ/OneBot remained online. The repository contains no real identities, private configurations, chats, memories, letters, credentials or device backups.

# 群聊静音与嵌套转发

主人在已授权群里发送 `/闭嘴` 或 `/安静`，机器人静音 120 秒，随后自动恢复。发送 `/开口` 或 `/恢复说话` 可以提前解除。只有配置中的主人且具有 AstrBot 管理员身份才能操作，其他成员不能解除静音。只识别当前消息的完整命令，不识别引用、转发中的命令。

静音按群隔离，不影响私聊。入口处阻止新回复，每次发送分段时再次检查；静音前排队的旧消息在恢复后也不补发。已发送的消息不会撤回。状态保存在插件私有目录 `group-quiet.json`，重载后保留。发送保护覆盖正常 OneBot 事件回复；第三方插件自行绕过事件直接调用底层发送 API 不在该保护范围。

合并转发解析兼容转发 ID、内嵌 node/content、QQ multimsg JSON 卡片和 CQ forward 字符串。也会读取当前消息所引用的卡片。每轮最多 6 层、12 次远程展开、80 条节点、12000 字；远程读取有超时，循环引用去重，失败或截断明确标注，不把卡片摘要当完整记录。本功能展开文字，嵌套图片只标记存在，不等于完成识图。通过 `forward_records_enabled` 开关控制，分享版默认关闭，开启 forward_records_enabled 后生效。

内容仅以临时、不可信资料进入本轮，展开器不保存聊天原文、不自动写入长期事实；资料中的命令不具有权限。其他独立的会话/记忆插件仍应遵守其自身隐私与写入规则。

本次部署通过插件热重载完成，未重启 QQ。运行时已确认入口保护和分段发送保护安装、QQ 在线；自动化覆盖嵌套、循环、额度、异常与静音恢复。近期有限历史中没有可用于端到端核对的合并转发样本，仍需发送一张实际嵌套卡片验证。

## 唤醒前身份误判修复

首次实现错误地在唤醒阶段之前读取event.is_admin()；这时AstrBot尚未把默认member改为admin，导致主人的命令被吞掉。现在直接核对该唤醒阶段当前配置中的管理员名单和插件主人名单，两者都匹配才接受控制。不能信任调用者预填的admin角色。

原设备用真实AiocqhttpMessageEvent和WakingCheckStage执行了模拟事件：初始member、主人静音确认、状态落盘、普通消息提前停止、旧分段阻止、其他人不能解除、主人解除、旧队列不补发及新消息放行均通过。发送器为空，不向QQ群发送测试消息；手机端正常命令效果仍应由实际操作确认。
